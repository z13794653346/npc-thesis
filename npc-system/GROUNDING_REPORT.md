# 无依据闲聊的审查与拒绝保存

日期：2026-09-20。范围：针对普通对话编造目击、亲历或交流细节增加事实审查；未修改论文、任务书、密钥或已有生产存档。

## 实现与验证结论

已实现“无动作草稿→独立事实审查→通过才展示并保存”的应用流程。审查拒绝、返回格式错误、超时都返回失败，不增加回合、不改变承诺期限、不写入玩家对话或角色记忆。重复请求返回原结果，不重新收费调用。

**这修复的是未经审查直接保存的问题，不代表彻底消除幻觉。** 真实测试证明旧错误样本能被拒绝，同时也暴露了语义审查的误判和漏判。拒绝保留在原始测试数据中，没有记成正常聊天成功。

## 修改内容

- `app/main.py`：增加严格的GroundingReview输出校验；supported必须为布尔true且unsupported_claims为空才能放行。生成与审查共用默认30秒截止时间。拒绝返回`ungrounded_reply`，原始草稿和审查结果仅进入受保护的调试记录。
- `app/llm.py`：独立审查提示和输入白名单。事实来源限定为角色、公开场景、当前可访问知识、有效检索记忆及可用操作；不传历史台词或玩家输入作为证据。转述不得升级成亲眼所见。生成温度0.2，审查0.0，并要求简短、基于设定的回答。
- `tests/test_api.py`：新增8项回归测试，覆盖无依据回复、矛盾审查结果、错误类型/缺字段、审查超时、旧对话与玩家说法不充当证据、动作无需语言审查、两次调用共享截止时间；更新原并发测试替身适配审查格式，保留409冲突断言。
- `scripts/live_grounding.py`：独立存档的小规模实测，当前最多12次模型调用，包含固定草稿审查和三角色真实对话。
- `scripts/live_smoke.py`：计数包含审查；完整原冒烟流程最多20次模型调用。`app/experiments.py`同步实际生成温度，避免日志参数与请求不一致。

没有新增生产依赖。涉及动作的草稿仍使用确定性规则结果替换，无需额外审查；纯规则按钮不调用模型。普通模型闲聊增加一次审查调用，延迟和费用会增加；不自动反复重写或重试以凑出可展示回答。

## 两轮真实调用：完整保留成功与失败

模型：`deepseek-flash`，DeepSeek官方接口。本次两轮共22次模型调用，含生成和审查，未获取账单；HTTP含重试最多44次，该数不是实际重试计数。

第一轮：`artifacts/live-grounding-20260920T053800-668e41/`，10次调用。3条旧错误草稿被拒绝，1条正确身份介绍通过；三角色新对话只有店主被放行，维修员和旅客被拒绝。人工发现店主回答仍有无依据细节被漏判，维修员审查把“姓周”也列为不支持。

第二轮：`artifacts/live-grounding-20260920T054358-c7118a/`，12次调用。降低随机性并补充已观察到的判别边界后：

- 3条旧错误草稿均被拒绝。
- 2条正确身份介绍通过，包括“维修员，姓周”。
- 新增“登记簿在柜台上、所有住客出入都记录”的无依据草稿被拒绝。
- 新生成的店主、维修员对话被放行；旅客回答因把公开敲门声转成自身亲历而被拒绝，未保存。此项在脚本中仍记为聊天失败。

第二轮6个固定审查样本符合预期，3条端到端对话中2条完成、1条拒绝。**不是9项全通过，也不能作为正式准确率。** 这些是针对已知错误编写/调整过的开发样本，不能代替独立测试集。

人工复核仍发现：放行的店主回答添加“门锁都归我管”等设定未明确提供的职责，审查有漏判；旅客审查理由也把部分已存在的公开事实一起列为不支持，理由质量仍不稳定。因此后续正式实验需要人工标注并分别报告漏判、误拒、可用性及调用成本，不能只统计审查器自己的通过值。

两轮目录中的JSON/JSONL已用实际本机密钥检查，未发现密钥值。原始生成、审查输入/输出、API结果和独立存档均保留。

## 使用与限制

```bash
# 仅在接受付费调用后运行，最多12次模型调用，含审查
PYTHONPATH=. .venv/bin/python scripts/live_grounding.py --confirm-paid
```

审查使用同一供应方模型的另一次独立调用，不是独立人工裁判，也不是确定性事实证明。温度0不保证绝对确定性。普通对话可能被误拒，界面会明确提示失败，可重试或使用规则按钮。

旧存档和旧请求结果不自动清除或改写；新的审查不会把旧台词作为事实依据，但玩家仍可看到已有历史。提示注入、罕见表达及语义漏判尚无全面保证。

本轮未运行正式108条记忆及108条泄漏实验。`app.experiments`测量单次原始生成与检索对照，不经过应用审查门禁，不应当作完整产品的最终输出质量。
